# ЧАСТЬ 1: .env файл

## Что такое .env?
`.env` — это файл с секретными настройками проекта.
`.env` = "environment variables" = переменные окружения.

Это как "конфигурационная карточка" проекта — там хранятся данные которые:
1. Нельзя показывать публично (пароли, секретные ключи)
2. Могут меняться на разных компьютерах (localhost у тебя, другой адрес на сервере)

## Содержимое нашего .env:
```
DB_HOST=localhost          # адрес сервера базы данных
DB_USER=root               # имя пользователя MySQL
DB_PASSWORD=***            # пароль от MySQL
DB_NAME=11UNITY_db         # имя нашей базы данных

JWT_SECRET=...             # секретный ключ для создания токенов
PORT=3000                  # на каком порту работает наш сервер
```

## Зачем .env а не просто написать в коде?
Плохо (НЕЛЬЗЯ так делать):
```js
password: 'neymar200410'  // пароль виден всем кто видит код!
```

Хорошо (правильный способ):
```js
password: process.env.DB_PASSWORD  // читается из .env — в коде пароля нет
```

## Почему .env не загружается на GitHub?
В файле `.gitignore` написано `.env` — это значит git игнорирует этот файл.
Если бы .env попал на GitHub — любой человек увидел бы твой пароль от базы данных!

# ЧАСТЬ 2: backend/config/database.js

## Что это такое?
Этот файл создаёт подключение к базе данных MySQL и экспортирует его.
Все контроллеры используют это подключение для выполнения SQL запросов.

## Разбор кода строчка за строчкой:

### Строка 1: подключение библиотеки
```js
const mysql = require('mysql2');
```
- `require()` — это способ подключить внешнюю библиотеку в Node.js (как import)
- `mysql2` — библиотека для работы с MySQL из JavaScript
- `const` — объявление константы (значение не изменится)

### Строки 12-22: создание пула подключений
```js
const pool = mysql.createPool({
    host: process.env.DB_HOST,        // 'localhost'
    user: process.env.DB_USER,        // 'root'
    password: process.env.DB_PASSWORD, // пароль из .env
    database: process.env.DB_NAME,    // '11UNITY_db'
    waitForConnections: true,          // ждать если нет свободных подключений
    connectionLimit: 10,               // максимум 10 одновременных подключений
    queueLimit: 0,                     // очередь без лимита (0 = безлимит)
    enableKeepAlive: true,             // держать подключение живым
    keepAliveInitialDelay: 0           // без задержки
});
```
- `process.env.DB_HOST` — читает значение из .env файла
- `process` — встроенный объект Node.js с информацией о процессе
- `process.env` — все переменные окружения (включая наш .env)

## Что такое Connection Pool (Пул подключений)?

Представь ресторан:
- Без пула: каждый посетитель ждёт пока повар выйдет, поговорит с ним, уйдёт, потом вернётся для следующего. Медленно!
- С пулом: есть 10 официантов (подключений). Каждый запрос берёт свободного официанта, получает ответ, официант освобождается.

Пул = заранее созданные готовые подключения к БД.
`connectionLimit: 10` = максимум 10 запросов к БД одновременно.

### Строки 27-29: обработка ошибок
```js
pool.on('error', (err) => {
    console.error('Database pool error:', err.message);
});
```
- `pool.on('error', ...)` — слушаем событие 'error' на пуле
- Если БД упала или потеряно соединение — выведет ошибку в консоль
- `(err) => { ... }` — это стрелочная функция (arrow function) в JS

### Строка 34: экспорт
```js
module.exports = pool;
```
- `module.exports` — экспортируем пул чтобы другие файлы могли его использовать
- Это как сказать: "этот файл предоставляет pool для использования"

## Как другие файлы используют этот пул?
```js
// В любом контроллере:
const pool = require('../config/database');

// И потом:
const [rows] = await pool.promise().query('SELECT * FROM users');
```

## 🔑 JS Концепции изученные в этом уроке

| Концепция | Объяснение |
|-----------|------------|
| `const` | Константа — значение нельзя переназначить |
| `require()` | Подключить модуль/библиотеку (Node.js способ) |
| `process.env` | Объект со всеми переменными окружения |
| `module.exports` | Экспортировать что-то из файла |

## ❓ Вопросы с защиты

**Q: Зачем нужен .env файл?**
A: Для хранения секретных данных (пароли, ключи) отдельно от кода. Код можно публиковать, .env — нельзя.

**Q: Что такое process.env?**
A: Это объект Node.js который содержит все переменные окружения. Библиотека dotenv загружает .env файл в process.env при старте сервера.

**Q: Зачем пул подключений вместо одного подключения?**
A: Один пользователь — один запрос к БД. Если на сайте 50 пользователей одновременно — нужно 50 подключений. Пул создаёт их заранее и переиспользует.

**Q: Что такое module.exports?**
A: Механизм экспорта в Node.js. Что ты экспортируешь из файла через module.exports — то и получишь при require() этого файла в другом месте.

**Q: Почему connectionLimit = 10?**
A: Баланс между производительностью и ресурсами сервера. Слишком много подключений — нагружает MySQL. 10 достаточно для нашего проекта.
