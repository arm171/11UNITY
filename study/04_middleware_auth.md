# 📁 Файл: backend/middleware/auth.js
## Что это такое?
Это middleware для защиты роутов. Проверяет — авторизован ли пользователь и есть ли у него нужная роль.
Без этого файла любой мог бы зайти на любой роут без входа в систему.

---

## Что такое JWT?

**JWT** = JSON Web Token — это "цифровой пропуск".

Как это работает в жизни:
```
1. Пользователь входит (email + пароль)
2. Сервер проверяет данные → создаёт JWT токен
3. Отправляет токен пользователю
4. Пользователь сохраняет токен (в браузере)
5. При каждом следующем запросе — отправляет токен
6. Сервер проверяет токен → если верный → пускает
```

Как выглядит JWT токен:
```
eyJhbGciOiJIUzI1NiJ9.eyJpZCI6MSwiZW1haWwiOiJ0ZXN0QHRlc3QuY29tIn0.abc123
```
Три части разделённые точкой:
- **Заголовок** (алгоритм шифрования)
- **Данные** (id пользователя, роль, время истечения)
- **Подпись** (проверка что токен не подделан)

Данные внутри токена ВИДНЫ всем (base64), но ИЗМЕНИТЬ нельзя — подпись не совпадёт!

## Разбор кода

### Функция 1: verifyToken (строки 16-38)
```js
const verifyToken = (req, res, next) => {
```
Это middleware функция — принимает req, res, next.

**Шаг 1 — достать токен из заголовка:**
```js
const authHeader = req.headers['authorization'];
const token = authHeader && authHeader.split(' ')[1];
```
Клиент отправляет заголовок в таком формате:
```
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```
- `req.headers['authorization']` → берём весь заголовок: `"Bearer eyJhbG..."`
- `.split(' ')` → разбиваем по пробелу: `["Bearer", "eyJhbG..."]`
- `[1]` → берём второй элемент (индекс 1): `"eyJhbG..."`
- `authHeader && ...` → если authHeader пустой (null) — не падаем, просто token = null

**Шаг 2 — проверить что токен есть:**
```js
if (!token) {
    return res.status(401).json({ message: 'Access token is required' });
}
```
Нет токена = не авторизован → 401

**Шаг 3 — проверить токен:**
```js
try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.user = decoded;
    next();
} catch (error) {
    return res.status(403).json({ message: 'Invalid or expired token' });
}
```
- `jwt.verify(token, secret)` — проверяет подпись токена с нашим секретным ключом
- Если токен верный → `decoded` = объект с данными: `{ id: 1, role: 'coach', email: '...' }`
- `req.user = decoded` → СОХРАНЯЕМ данные пользователя в запрос (для следующих middleware!)
- `next()` → пропускаем дальше
- Если токен неверный/истёк → catch поймает ошибку → 403

**try/catch в JS:**
```js
try {
    // рискованный код — может выбросить ошибку
} catch (error) {
    // если ошибка — выполнится этот блок
}
```

### Функция 2: checkRole (строки 47-66)
```js
const checkRole = (roles) => {
    const rolesArray = Array.isArray(roles) ? roles : [roles];
    return (req, res, next) => {
        ...
    };
};
```

Это **функция которая возвращает функцию** (очень важная JS концепция!).

**Зачем так сделано?**
Потому что нам нужно ПЕРЕДАТЬ параметр (список ролей) в middleware.
Обычный middleware принимает только (req, res, next) — нет места для параметров.
Решение: функция-обёртка принимает параметр и возвращает готовый middleware.

**Пример использования:**
```js
// В роуте:
router.post('/create', verifyToken, checkRole('organizer'), createTournament)
//                                  ↑ вызываем checkRole('organizer')
//                                    она возвращает middleware функцию
```

**Разбор checkRole:**
```js
const rolesArray = Array.isArray(roles) ? roles : [roles];
```
Тернарный оператор: `условие ? если_да : если_нет`
- Если передали массив `['coach', 'organizer']` → оставляем как есть
- Если передали строку `'organizer'` → оборачиваем в массив `['organizer']`

```js
if (!rolesArray.includes(req.user.role)) {
    return res.status(403).json({ message: 'Access denied' });
}
```
- `includes()` — проверяет есть ли элемент в массиве
- Если роль пользователя НЕ входит в список разрешённых → 403 Forbidden

## 🔒 Как используется в роутах (пример)

```js
// Открытый роут — без защиты:
router.post('/login', loginUser);

// Защищённый роут — нужна авторизация:
router.get('/profile', verifyToken, getProfile);

// Роут только для организатора:
router.post('/tournament', verifyToken, checkRole('organizer'), createTournament);

// Роут для тренера или организатора:
router.get('/teams', verifyToken, checkRole(['coach', 'organizer']), getTeams);
```

Порядок важен: сначала verifyToken (проверить токен), потом checkRole (проверить роль).

## ❓ Вопросы с защиты

**Q: Что такое JWT и зачем он нужен?**
A: JSON Web Token — цифровой пропуск. После входа сервер создаёт токен с данными пользователя и подписью. Клиент хранит его и отправляет при каждом запросе. Сервер проверяет подпись — если верная, пропускает.

**Q: Почему 401 в одном случае и 403 в другом?**
A: 401 (Unauthorized) — пользователь не представился (нет токена). 403 (Forbidden) — пользователь известен, но у него нет прав (неверная роль или истёкший токен).

**Q: Что такое req.user и зачем это нужно?**
A: После verifyToken мы кладём данные пользователя в req.user. Следующие middleware и контроллеры могут оттуда достать id, роль без повторной проверки токена.

**Q: Зачем checkRole возвращает функцию а не является функцией?**
A: Middleware принимает только (req, res, next). Чтобы передать параметр (список ролей) — нужна обёртка. checkRole('organizer') возвращает готовый middleware с "запомненным" параметром.

**Q: Можно ли подделать JWT токен?**
A: Данные токена видны (base64), но изменить их нельзя — подпись создаётся с JWT_SECRET который знает только сервер. Если данные изменить — подпись не совпадёт и jwt.verify выбросит ошибку.
