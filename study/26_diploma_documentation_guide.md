## Раздел 1: Введение

### Цель работы:
Разработка веб-платформы для организации и управления любительскими футбольными турнирами, позволяющей автоматизировать процессы регистрации команд, формирования расписания матчей и ведения статистики.

### Задачи:
- Проектирование реляционной базы данных
- Разработка REST API на Node.js + Express
- Реализация SPA (Single Page Application) на чистом JavaScript
- Реализация системы аутентификации с JWT
- Реализация реалтайм обновлений через WebSocket
- Поддержка нескольких языков (i18n): English, Русский, Հայերեն, ქართული
- Поддержка трёх форматов турниров: лига, плей-офф, группа+плей-офф

### Актуальность:
Любительские футбольные турниры часто организуются вручную (таблицы Excel, мессенджеры). Автоматизация снижает ошибки, экономит время, повышает прозрачность для участников.

## Раздел 2: Технологии

### Таблица технологий:

| Технология | Версия | Назначение |
|-----------|--------|-----------|
| Node.js | 18+ | Runtime для серверного JavaScript |
| Express.js | 4.x | Веб-фреймворк для REST API |
| MySQL | 8.0 | Реляционная СУБД |
| mysql2 | 3.x | Драйвер MySQL для Node.js |
| Socket.IO | 4.7 | WebSocket для реалтайм коммуникации |
| JWT (jsonwebtoken) | 9.x | Аутентификация |
| bcrypt | 5.x | Хеширование паролей |
| Nodemailer | 6.x | Отправка email |
| express-rate-limit | 7.x | Защита от брутфорса |
| HTML5 / CSS3 / JS (ES6+) | - | Frontend без фреймворков |

### Обоснование выбора:
- **Node.js**: единый язык (JavaScript) для frontend и backend
- **MySQL**: реляционная БД подходит для связанных данных (команды → турниры → матчи)
- **Vanilla JS**: понимание основ без скрытой магии фреймворков
- **JWT**: stateless авторизация, не требует хранения сессий на сервере

## Раздел 3: Проектирование

### ER-диаграмма (для рисования):

```
users ──────── teams (coach_id → users.id)
  │               │
  │               ├── team_players (team_id, player_id)
  │               │
  │         tournament_teams (team_id, tournament_id, status)
  │               │  status: 'pending' → 'approved'
tournaments ──────┘
  │
  ├── matches (tournament_id, team1_id, team2_id)
  │       │
  │       └── match_events (match_id, player_id)
  │
  ├── standings (tournament_id, team_id)
  └── player_statistics (tournament_id, player_id)
```

## Раздел 4: Реализация — ключевые моменты

### API маршруты:

| Метод | URL | Доступ | Описание |
|-------|-----|--------|---------|
| POST | /api/auth/register | Public | Регистрация |
| POST | /api/auth/login | Public | Вход |
| GET | /api/auth/verify/:token | Public | Подтверждение email |
| POST | /api/auth/forgot-password | Public | Сброс пароля |
| POST | /api/auth/reset-password | Public | Новый пароль |
| GET | /api/tournaments | Auth | Список турниров |
| POST | /api/tournaments | Organizer | Создать турнир |
| POST | /api/tournaments/:id/join | Coach | Заявка на участие (статус pending) |
| GET | /api/tournaments/:id/pending-teams | Organizer | Список заявок на рассмотрении |
| POST | /api/tournaments/:id/teams/:teamId/approve | Organizer | Принять заявку команды |
| POST | /api/tournaments/:id/teams/:teamId/reject | Organizer | Отклонить заявку команды |
| GET | /api/teams | Auth | Список команд |
| POST | /api/teams | Coach | Создать команду |
| GET | /api/statistics | Auth | Глобальная статистика |
| GET | /api/statistics/tournament/:id | Auth | Статистика турнира |

### Алгоритм генерации матчей (league):
```
Для N команд, круговой турнир:
- Количество туров = N - 1 (если N чётное)
- Матчей в туре = N / 2
- Всего матчей = N * (N-1) / 2

Алгоритм "round-robin":
  Фиксируем одну команду, остальные N-1 ротируем по кругу.
  В каждом туре: команда[0] vs команда[N-1], команда[1] vs команда[N-2], ...
```

### Алгоритм плей-офф:
```
8 команд → 3 раунда:
  Раунд 1 (Четвертьфинал): 4 матча → 4 победителя
  Раунд 2 (Полуфинал): 2 матча → 2 победителя
  Раунд 3 (Финал): 1 матч → 1 победитель

Сетка: bracket_slot определяет позицию пары в следующем раунде
  Победитель матча slot=0 встречается с победителем slot=1
  Победитель slot=2 встречается с победителем slot=3
  ...
```

## Раздел 5: Тестирование

### Ключевые тест-кейсы:

| # | Тест | Ожидаемый результат | Фактический |
|---|------|---------------------|-------------|
| 1 | Регистрация с существующим email | Ошибка "Email already exists" | ✓ |
| 2 | Вход с неверным паролем | Ошибка + rate limit после 5 попыток | ✓ |
| 3 | Создание турнира без токена | 401 Unauthorized | ✓ |
| 4 | Player пытается создать турнир | 403 Forbidden | ✓ |
| 5 | Генерация матчей для 4 команд | 6 матчей в 3 тура | ✓ |
| 6 | Изменение счёта обновляет standings | Очки пересчитываются | ✓ |
| 7 | Смена языка на RU | Весь UI переводится | ✓ |
| 8 | Сброс пароля с истёкшим токеном | Ошибка "Invalid token" | ✓ |
| 9 | Тренер подаёт заявку на турнир | Статус pending, команда не в турнире | ✓ |
| 10 | Организатор принимает заявку | Команда переходит в статус approved, счётчик +1 | ✓ |
| 11 | Организатор отклоняет заявку | Запись удаляется, тренер может подать снова | ✓ |

## Раздел 6: Заключение

### Что реализовано:
- Полноценная веб-платформа с аутентификацией и ролевой системой
- Три типа турниров с автоматической генерацией расписания
- Реалтайм обновления результатов через WebSocket
- Автоматический подсчёт статистики (голы, передачи, карточки, очки)

- Email-подтверждение и восстановление пароля

### Перспективы развития:
- Мобильное приложение (React Native)
- Загрузка фотографий команд и игроков
- Push-уведомления о матчах
- Онлайн трансляция матчей (live commentary)
- Платёжная система для взносов участников
