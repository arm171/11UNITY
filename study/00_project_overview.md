# 🏠 Обзор проекта 11UNITY
## Как создавался проект и почему в таком порядке

---

## Что такое 11UNITY?

**11UNITY** — это веб-платформа для управления футбольными турнирами.
Дипломная работа. Стек технологий:

| Часть | Технология | Зачем |
|-------|-----------|-------|
| Frontend | HTML + CSS + Vanilla JS | Что видит пользователь |
| Backend | Node.js + Express.js | Сервер, обработка запросов |
| База данных | MySQL | Хранение всех данных |
| Реалтайм | Socket.IO | Обновления без перезагрузки |
| Email | Nodemailer | Подтверждение почты, сброс пароля |

---

## Три роли пользователей

```
👤 PLAYER (Игрок)
   - регистрируется на сайте
   - вступает в команду
   - видит свою статистику (голы, передачи, карточки)

🏋️ COACH (Тренер)
   - создаёт команду
   - добавляет игроков
   - подаёт заявку на турнир

🏆 ORGANIZER (Организатор)
   - создаёт турниры (league / playoff / group+playoff)
   - подтверждает/отклоняет заявки команд
   - вводит счёт матчей
   - управляет своими турнирами
```

## Порядок создания проекта (и почему именно так)

### Аналогия: строительство дома

```
HTML     = Каркас (стены, комнаты, дверные проёмы)
CSS      = Отделка (покраска, плитка, красота)
БД       = Фундамент (план куда что хранить)
Backend  = Коммуникации (вода, свет, невидимое но нужное)
JS       = Автоматизация (умный дом: кнопки, датчики, реакция)
```

### Шаг 1: HTML (структура)
**Почему первый?** Нельзя стилизовать или программировать то, чего нет.
HTML — это чертёж. Сначала решаем: какие секции, кнопки, формы нужны.
```html
<section id="tournaments">
    <div id="tournaments-list">...</div>
</section>
```

### Шаг 2: CSS (внешний вид)
**Почему второй?** Структура уже есть — теперь делаем её красивой.
CSS описывает КАК выглядят элементы. Без HTML — CSS бессмысленен.
```css
.stat-card {
    background: rgba(255,255,255,0.05);
    border-radius: 12px;
    padding: 24px;
}
```

### Шаг 3: База данных (schema.sql)
**Почему перед backend?** Сервер должен знать где и как хранить данные.
Сначала создаём таблицы — потом пишем SQL запросы к ним.

### Шаг 4: Backend (Node.js + Express)
**Почему перед JS?** Frontend должен знать что запрашивать.
API маршруты (`/api/tournaments`, `/api/teams`) должны существовать
прежде чем frontend будет к ним обращаться.

### Шаг 5: Frontend JS
**Почему последний?** JS — клей между HTML и backend.
`fetch('/api/tournaments')` → данные → обновить HTML.
JS связывает кнопки с сервером.

## Архитектура: Client-Server

```
╔══════════════════╗         HTTP запрос         ╔══════════════════╗
║    БРАУЗЕР       ║  ─────────────────────────► ║    СЕРВЕР        ║
║   (Frontend)     ║                             ║   (Backend)      ║
║                  ║ ◄─────────────────────────  ║                  ║
║  HTML + CSS + JS ║         JSON ответ          ║  Express + MySQL ║
╚══════════════════╝                             ╚══════════════════╝
```

**Клиент** (браузер) — отображает данные, принимает ввод пользователя.
**Сервер** — хранит данные, проверяет права, выполняет логику.
**HTTP** — протокол общения. Запрос → Ответ.

## Типы турниров

### League (Лига)
- Каждая команда играет против каждой (круговой турнир)
- Результат: турнирная таблица с очками
- Победа = 3 очка, Ничья = 1, Поражение = 0

### Playoff (Плей-офф)
- Кубковая система: проигравший выбывает
- 8 команд → Четвертьфинал → Полуфинал → Финал
- Результат: визуальная сетка (bracket)

### Group + Playoff (Группа + Плей-офф)
- Сначала групповой этап (лига)
- Потом лучшие идут в плей-офф
- Самый сложный формат

## Ключевые технологии кратко

| Технология | Что делает в проекте |
|-----------|---------------------|
| **Express.js** | Веб-фреймворк. Маршрутизация URL, middleware, ответы |
| **MySQL2** | Драйвер для работы с MySQL из Node.js |
| **JWT** | JSON Web Token — безопасная авторизация без сессий |
| **bcrypt** | Хеширование паролей (нельзя расшифровать) |
| **Socket.IO** | WebSocket — двустороннее соединение (реалтайм) |
| **Nodemailer** | Отправка email через SMTP |
| **express-rate-limit** | Защита от брутфорса (лимит запросов) |
| **cors** | Cross-Origin Resource Sharing — разрешает запросы с другого порта |
| **dotenv** | Загружает переменные из .env файла |

## Вопросы с защиты

**Q: Почему выбрали именно этот стек?**
A: Node.js — JavaScript и на backend и на frontend (один язык). MySQL — реляционная БД для структурированных данных с отношениями (команды, турниры, матчи). Express — минималистичный фреймворк, легко изучить. Vanilla JS — без фреймворков, чистый JS, проще понять архитектуру SPA.

**Q: Что такое REST API?**
A: Архитектурный стиль. GET — получить данные, POST — создать, PUT/PATCH — изменить, DELETE — удалить. Каждый URL — это ресурс. `/api/tournaments` — все турниры, `/api/tournaments/5` — конкретный турнир.

**Q: Зачем три роли?**
A: Разные права — разные возможности. Организатор управляет турнирами, тренер управляет командой, игрок только участвует. Это называется RBAC — Role Based Access Control.

**Q: Что такое JWT и зачем он?**
A: JSON Web Token. После входа сервер выдаёт токен с зашифрованными данными пользователя. При каждом запросе frontend отправляет этот токен. Сервер проверяет токен без обращения к БД. Альтернатива — сессии (хранить на сервере), но JWT масштабируется лучше.
